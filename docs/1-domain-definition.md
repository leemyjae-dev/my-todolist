## 1. 목적/배경

- 인증된 사용자 개인별로 할일을 관리할 수 있는 서비스가 부재하다.
- 기존 할일 관리 방식은 시작일과 종료일을 다루지 못해 일정 기반 관리가 어렵다.
- 본 문서는 my-todoList 서비스의 핵심 도메인 개념, 규칙, 유스케이스를 정의하여 이후 설계/개발의 공통 기준(Ubiquitous Language)으로 삼는다.

## 2. 핵심 용어 정의 (Ubiquitous Language)

| 용어 | 정의 |
|---|---|
| 사용자 (User) | 회원가입 후 인증을 통해 서비스를 이용하는 주체. 자신의 카테고리/할일만 소유·관리한다. |
| 카테고리 (Category) | 할일을 분류하는 단위. 사용자별로 존재하며, 미지정 시 '기본' 카테고리가 적용된다. |
| 할일 (Todo) | 사용자가 등록하는 작업 단위. 제목, 시작일, 종료일, 완료 여부 등을 가진다. |
| 상태 (Status) | 할일의 진행 상태. 시작 전 / 진행중 / 완료 / 지연(Overdue) 중 하나로 계산된다. |
| 지연 (Overdue) | 종료일이 지났음에도 완료되지 않은 할일의 상태. |

## 3. 핵심 도메인 개념 및 속성

### 3.1 User (엔티티)

| 필드 | 타입 | 제약조건 |
|---|---|---|
| id | UUID/Long | PK |
| email | String | 필수, 고유(unique), 로그인 식별자 |
| password | String | 필수, 8자 이상, 해시 저장(평문 저장 금지) |
| name | String | 필수, 1~50자 |
| createdAt | DateTime | 자동 생성 |
| updatedAt | DateTime | 정보 수정 시 갱신 |

### 3.2 Category (엔티티)

| 필드 | 타입 | 제약조건 |
|---|---|---|
| id | UUID/Long | PK |
| userId | FK(User) | 필수, 소유자 |
| name | String | 필수, 사용자별 고유(동일 사용자 내 중복 불가) |
| isDefault | Boolean | 기본값 false. 사용자당 '기본' 카테고리는 시스템이 자동 생성하며 true |

- '기본' 카테고리(isDefault=true)는 삭제할 수 없다.
- 일반 카테고리 삭제 시 소속 Todo는 삭제되지 않고 '기본' 카테고리로 자동 이동한다.

### 3.3 Todo (엔티티)

| 필드 | 타입 | 제약조건 |
|---|---|---|
| id | UUID/Long | PK |
| userId | FK(User) | 필수, 소유자 |
| categoryId | FK(Category) | 필수. 등록 시 미지정이면 해당 사용자의 '기본' 카테고리로 설정 |
| title | String | 필수, 1자 이상 |
| description | String | 선택 |
| startDate | Date | 필수 |
| endDate | Date | 필수, startDate 이상이어야 함 (startDate <= endDate) |
| isCompleted | Boolean | 기본값 false |
| completedAt | DateTime | isCompleted=true로 전환 시 기록, 선택 |
| createdAt | DateTime | 자동 생성 |
| updatedAt | DateTime | 수정 시 갱신 |

> 상태(Status)는 별도 저장 필드가 아니라 startDate/endDate/isCompleted와 현재 날짜(today)를 기반으로 계산되는 파생 값이다.

## 4. 할일 상태(Status) 정의 및 전이 규칙

| 상태 | 판정 조건 |
|---|---|
| 시작 전 (NOT_STARTED) | isCompleted = false 이고 today < startDate |
| 진행중 (IN_PROGRESS) | isCompleted = false 이고 startDate <= today <= endDate |
| 지연 (OVERDUE) | isCompleted = false 이고 today > endDate |
| 완료 (COMPLETED) | isCompleted = true (날짜와 무관하게 최우선 적용) |

- today는 서버 UTC 자정(00:00:00) 기준 날짜로 판정한다.
- 상태는 조회 시점마다 위 조건을 순서대로 평가하여 계산한다 (완료 여부를 최우선으로 판정).
- 사용자가 완료 처리(isCompleted=true)하면 날짜 조건과 무관하게 즉시 완료 상태가 된다.
- 완료 취소 시 completedAt은 초기화되고, 날짜 기준으로 상태가 재계산된다(시작 전/진행중/지연 중 하나로 복귀).

## 5. 핵심 비즈니스 규칙

| ID | 규칙 |
|---|---|
| BR-01 | 회원가입한 사용자만 로그인 후 서비스를 이용할 수 있다. |
| BR-02 | 사용자 가입 시 '기본' 카테고리가 자동 생성된다. |
| BR-03 | 할일 등록 시 카테고리를 지정하지 않으면 '기본' 카테고리가 적용된다. |
| BR-04 | 할일의 시작일은 종료일보다 늦을 수 없다 (startDate <= endDate). |
| BR-05 | 사용자는 자신이 소유한 카테고리/할일만 조회·수정·삭제할 수 있다 (소유권 검증 필수). 타 사용자 리소스 접근 시 404로 응답하여 존재 여부를 노출하지 않는다. |
| BR-06 | 할일 목록은 카테고리, 상태(시작 전/진행중/완료/지연)를 기준으로 필터링할 수 있다. |
| BR-07 | 이메일은 사용자 식별자로서 고유해야 하며, 로그인 시 인증 정보로 사용된다. |
| BR-08 | '기본' 카테고리는 삭제할 수 없다. 일반 카테고리 삭제 시 소속 Todo는 '기본' 카테고리로 이동한다. |
| BR-09 | 사용자는 새 카테고리를 생성할 수 있으며, 이름은 사용자별로 고유해야 한다(3.2 제약과 동일). |

## 6. 유스케이스 요약

| ID | 유스케이스 | 설명 | 관련 규칙 |
|---|---|---|---|
| UC-01 | 회원가입 | 이메일/비밀번호/이름으로 계정을 생성하고 기본 카테고리를 자동 생성한다. | BR-02, BR-07 |
| UC-02 | 로그인 | 이메일/비밀번호로 인증 후 서비스 이용 권한(세션/토큰)을 획득한다. | BR-01, BR-07 |
| UC-03 | 내 정보 수정 | 로그인한 사용자가 이름, 비밀번호 등 자신의 정보를 수정한다. | BR-05 |
| UC-04 | 할일 등록 | 카테고리(선택, 미지정 시 기본), 제목, 시작일/종료일(캘린더 선택)을 입력하여 할일을 생성한다. | BR-03, BR-04, BR-05 |
| UC-05 | 할일 목록 조회/필터링 | 카테고리별, 상태별(시작 전/진행중/완료/지연)로 목록을 필터링하여 조회한다. | BR-06 |
| UC-06 | 할일 수정 | 소유자가 편집 화면에서 제목/카테고리/일정/완료 여부 등을 수정한다. | BR-04, BR-05 |
| UC-07 | 할일 삭제 | 소유자가 자신의 할일을 삭제한다. | BR-05 |
| UC-08 | 카테고리 삭제 | 소유자가 일반 카테고리를 삭제하면 소속 Todo는 기본 카테고리로 이동한다. | BR-08, BR-05 |
| UC-09 | 카테고리 생성 | 사용자가 이름을 입력해 새 카테고리를 생성한다. | BR-09 |

## 7. 범위 외 (Out of Scope)

- 알림/리마인더 기능
- 반복 일정(recurring todo) 처리
- 첨부파일, 댓글 등 부가 기능
- 소셜 로그인, 비밀번호 재설정 등 인증 확장 기능
